Development history

How Still's identity changed, which decisions were dropped and what replaced them, and what happened in each period, following the compendium's record.

Manuscripts: Compendium ch. 4, 18–19. Last updated October 14, 2026. All dates are in 2026.

Before you read

Issue numbers in the compendium (such as #712) refer to issues or pull requests in the predecessor repository Jongtae/agentos, not this one. This guide does not carry the numbers over and describes events by date and content. Most of the record here is past decisions and their reasons, content labelled Historical or Contract, not current features.

How the identity changed

Basis Historical. Compendium 4.1–4.4

Still's identity changed several times in forty days. What did not change was a single question: borrow the brain, keep the assistant.

  • September 5, a multi-tenant platform on Kubernetes. The first execution design pictured a Kubernetes-based agent platform isolated per user by namespace, with default-deny egress. The first pivot happened inside that document: the product unit changed from per-task execution to a persistent environment per owner. One sentence survives today: product work state is owned by PostgreSQL, and Kubernetes owns the state of execution resources. It is the first form of separating durable state from replaceable workers.
  • September 6, a one-day pivot. The Kubernetes direction was dropped almost at once. Still 0.2 ran as a single local process installed with Homebrew and read files only inside connected folders. It passed 42 automated tests and five acceptance cases in the same conversation. A later plan fixed the direction of no Docker or Kubernetes dependency.
  • September 7, Hub v2. It separated four layers: the Mac, Still (an always-running personal-state runtime), Codex and Claude Code (engines called per task), and a control plane (account and operations metadata only). The key sentence was that Still is not a mere relay: it decides which assistant to assign, supplies only permitted context, and holds tool execution, approval, cancellation, retry and evidence.
  • September 8, the first closeout. Master Plans 1 and 2 validated against mock contracts before any real credential was entered. The first closeout declared "development complete" on repository and CI evidence while explicitly excluding real subscription login, external connections, operating deployment and real-use success, and forbade relabelling an engineering gap as owner setup. The discipline was not perfect from the start. Work that produced only unconnected mock adapters was called complete until a remediation sequence, and an operating-readiness "ready" claim turned out to be false and was corrected. The evidence discipline did not hold by itself; it had to be re-established again and again.

Personal AI Kernel and Agent Distribution Platform

Basis Contract. Compendium 4.5

In this period the product's long-term identity was set down in one sentence: an owner-authoritative Personal AI Kernel plus an open Agent Distribution Platform. The kernel is agent-independent; the product experience and the distribution platform may be agent-centric. The documents also repeat what the product is not: not a chatbot, a coding harness, a swarm framework, a host kernel or hypervisor, or a replacement for macOS or Linux. They take particular care that the GitHub issues, pull requests, CI and delegation automation used to build the repository are not mistaken for the product itself.

The platform foundation fixed the schemas for the ten kernel concepts and the AgentPackage manifest. The follow-up work in that line and the useful-default-agent issues, however, were closed as not planned on September 24. The platform remained a long-term direction, and the immediate focus moved to an assistant genuinely useful to one person.

How real use changed direction

Basis Historical, Observed. Compendium 4.6–4.7

From late September, problems found in the owner's own use set the direction.

  • September 23, Presence research. It recorded that Telegram felt like a task and status console, that failures sent the owner to a management screen instead of continuing the conversation, and that the configured AI and the actual execution path differed. The problem was not tone but projection: internal concepts leaking into the conversation.
  • September 24, the decision model. A model-backed judgment boundary was chosen instead of a rule engine.
  • September 26, Secretary. The owner raised the problem that the decision model had become a rule-bound blocker instead of a gate for finding alternatives. The pilot posture then removed protection layers from the request path.
  • September 27, "AI is the engine". A constitutional principle came out of the realization that the repository was accumulating per-request features, such as directions and carts, in Still code.
  • October 10, Connect. The goal that handles every service through the flow of the Connection and Delegation Contract became active, and the Secretary program paused at an exact resume point.
  • October 10, the secretary is a starting point, not a boundary. The Professional Roles and Communication Contract widened the product thesis: Still is not a secretary-only app but an owner-centred operating environment for many professional roles. The same contract drew the line that a role creates no authority.

The current public release at the time of the compendium is v1.3.0 (October 10, 2026). Autonomous purchasing, arbitrary computer use, universal web verification, live stock and checkout verification, arbitrary third-party package execution and a public marketplace remain "no current claim" (see What is not claimed now).

Dropped decisions and their replacements

Basis Historical. Compendium ch. 18

This project does not erase what it drops. Issues closed as not planned remain design records, and removed protections remain in archive documents. If something is needed again, a small successor is created from the then-current architecture instead of reopening the old issue. A selection of rows from the compendium's table follows.

A few currents run through the compendium's table.

  • Remove rather than add. Many decisions removed the layers that crept in between the AI and the owner rather than adding guards or branches when something failed.
  • Protection is a dial, not a ratchet. Sensitivity judgments, private/public separation and ask-first were built and then removed for the pilot. The two invariants, secrets and payment, stayed throughout. What was removed was not declared wrong but deferred to a separately activated hardening program.
  • Scenario-specific code is not a fight won once. The principle that AI is the engine, its amendment and the Secretary program's founding rule all restate the same constraint. Sliding toward task-specific implementation is a standing pressure that has to be pushed back at every new feature.
  • Usefulness over ambition. The big vision of a marketplace and registry was not left quietly open but closed as not planned, with the design kept as citable history.

The most recent turning point in the repository, as the compendium records it, is procedural memory. Instead of rediscovering API documentation from scratch for every request, it would accumulate, per connection, function libraries that are verified, parameterized and gated by outcomes. It too requires generality guards from the start, and it cites research showing that naive AI self-generated skills performed poorly. This is at the contract stage and in progress, not a claim that it works.
