Memory and personal state

Moving memory is broader than exporting a conversation history. This page explains three levels of moving memory, memory versus authority, the difference between context and memory, and Still’s current memory policy.

Manuscripts: Whitepaper ch. 4, Compendium §5.1, 5.3, 7.4, 7.9 and ch. 24. Last updated October 14, 2026.

Three levels of moving memory

Basis Proposal. Whitepaper §4.1

The whitepaper separates three levels of moving memory.

Moving data
Bringing records over in a readable format.
Moving meaning
Preserving whether a record is a fact, a user preference or a model’s guess, and whether it was later corrected.
Continuity of use
Applying that information appropriately in the new environment so the user does not have to repeat what they already explained or corrected.

Example If “I’d rather avoid beef on weekdays” is saved as “vegetarian”, the data moved but the meaning was distorted. Carrying a temporary business-trip condition over as a permanent lifestyle preference is the same.

So the whitepaper proposes that a move carry, along with the content, its source, time, scope, whether the user confirmed it, its correction history and its validity period. What moves is stored information that can be checked. It is not a promise to move learning effects that exist only inside a model, or state that cannot be seen from outside.

How this differs from existing features

Basis Case. Whitepaper §4.2

Features that support moving memory already exist. Anthropic’s official guide describes importing memory from and exporting it to other AI providers, and says importing is experimental and may not always be applied successfully.

So the problem is not that “nobody can move memory”. The next step the whitepaper asks for is transfer quality the user can check: what moved, what was left out and what meaning changed.

Moving memory is not copying authority

Basis Proposal. Whitepaper §4.3

Knowing that a user prefers a particular bookstore is separate from the authority to buy from that bookstore account. Moving an ongoing purchase review is also different from moving the authority to pay. The transfer procedure the whitepaper proposes is as follows.

  • Check again in the new environment which authority is needed.
  • Show the transfer result as imported items, excluded items, conflicting items and items that could not be checked.
  • If an old record conflicts with a recent explicit correction, the old record is not revived. Memory that was withdrawn or corrected is not revived either.
  • Imported sentences are reference data, not commands that grant new authority. Connection secrets are not moved inside a memory bundle.
  • Existing material is not deleted automatically before the user has checked the result in the new environment.

The final test of Portable Memory is not whether data can be exported, but whether the user can still control their context after moving to another environment.

Whitepaper §4.3

This standard applies to Still itself. If it can connect many models but cannot be left, it has gained model independence but not enough user independence.

Context is not memory

Basis Contract. Compendium §5.1, 5.3, Development Constitution C5

Still separates context from memory. Context is the information given for one Work. Its usable scope and source are set, it expires, and it does not automatically become memory. Memory is the canonical record that Still manages.

A whole conversation, a model’s reasoning, search results and file content do not automatically become canonical memory. A package’s or external runtime’s internal state does not either. Memory that a third party wants to save stays a candidate (MemoryCandidate) until it is approved.

The current memory policy

Basis Contract·Implemented. Compendium §7.4

At first, only what the owner explicitly asked to be remembered and then confirmed became canonical. In real use, though, being asked about every fact to remember was itself a bad experience. So the policy changed as follows.

Saving immediately without asking applies only to the AI the owner chose. Third parties such as package tools and delegated specialists still save candidates. Values that look like passwords or tokens are not saved.

Note A remaining risk is also on record. A save induced by text on an untrusted web page can become current memory at once. Today this is mitigated only by attribution and undo; the defence against such attacks (injection) is parked.

Correct, forget, delete completely

Basis Contract. Compendium §7.9

Correcting and forgetting memory happens in the conversation, without a management console. The contract separates three operations.

Correct
Fix it in conversation, as in “you remembered that wrong”. It distinguishes “it was wrong” from “it is no longer true”.
Forget
Stop using it right away, keep only a receipt without the content, allow an undo for 7 days, then purge.
Delete completely
Purge immediately with no undo, reporting success, partial success and failure distinctly.

Forgetting locally is not claimed to erase copies held by the AI provider, exported files or backups. These three operations are set by contract, but their implementation is not finished yet.

Remaining problems

Source Compendium ch. 24

  • How to show how confident an agent is in a fact has not been settled. No standard or product defining this was found, and the design judgment so far is only to show it in a few categories instead of a number.
  • The correct, forget and delete contract and the research on forgetting at the database level are not yet connected to each other.
  • The current memory store records neither a validity period nor a retraction time.

Other open questions are in What is confirmed and open questions.
