확인된 범위와 열린 질문

이 페이지는 두 원고가 확인한 것과 확인하지 못한 것을 나눕니다. Still의 증거 경계, 아직 실시하지 않은 검증 계획, 열린 질문을 정리합니다.

원고: 백서 12–13장, 총람 22–24장. 최종 갱신 2026년 10월 14일.

사례이지 증명이 아닙니다

근거 관찰. 백서 12장, 총람 22.1절

두 원고는 Still을 산업의 미래를 증명한 완성품으로 보지 않습니다. 산업이 던져야 할 질문을 구체적으로 만들고, 무엇을 검증해야 하는지 끌어내는 개발 사례로 다룹니다.

2026년 9월 23일의 실사용 연구에서 두 가지가 드러났습니다. 작업 실행을 관리하는 내부 구조가 있는 것과, 사용자가 계속 이어지는 상대와 함께 일한다고 느끼는 것은 별개입니다. 선택 화면이 있는 것과, 그 선택이 실제 실행에 반영되는 것도 다릅니다.

한 프로젝트의 관찰은 산업 전체의 발생 빈도를 증명하지 않지만, 산업이 무엇을 검증해야 하는지를 구체적으로 제시할 수 있다.

백서 12장

지금 주장하지 않는 것

근거 계약. 총람 22.2절, 제품 현황 문서

제품 현황 문서는 다음 기능을 지금 할 수 있다고 주장하지 않습니다.

  • 스스로 알아서 하는 구매
  • 컴퓨터의 아무 작업이나 대신 조작하기
  • 어떤 웹사이트에서든 결과를 확인하는 기능
  • 실시간 재고와 결제 과정의 확인
  • 아무 외부 패키지나 실행하기
  • 공개 에이전트 마켓플레이스

아직 관찰되지 않은 것도 있습니다. 소유자 계정에서 판단 모델이 실제로 동작하는 모습, 실제 Telegram 동작이 자동 시험의 예상과 달랐던 원인, 실제 사이트에서 모델이 스킬의 방법을 얼마나 따르는지, 미리 준비하지 않은 서비스 요청을 실제로 끝까지 이어서 처리하는지입니다.

검증 의제

근거 제안. 백서 13장

동의하기 쉬운 원칙을 늘어놓는 데서 멈추지 않으려면, 실제로 비교해 보는 실험이 필요합니다. 백서가 제안한 항목은 다음과 같습니다.

주의 이 표는 실시한 실험의 결과가 아닙니다. 실험 인원, 반복 횟수, 예산, 사전 판정 기준은 아직 정해지지 않았습니다.

백서는 평가 조건도 적습니다. 성공 사례만 고르지 않고, 모델을 바꾸는 도중의 장애, 오래된 기억이 섞여 드는 경우, 권한 만료, 사용자의 중간 수정, 결과를 확인하지 못한 행동도 포함합니다. 판정 기준은 결과를 본 뒤가 아니라 실험 전에 정합니다. 충분히 동작하는 통합형 제품도 비교 대상에 둡니다.

실험에서 기억을 옮겨 얻는 이득이 작거나, 독립적인 에이전트 계층의 복잡성과 비용이 편익을 계속 넘는다면 제품 전략을 수정해야 한다고 백서는 적습니다.

열린 질문

출처 총람 24장

권한과 보호

  • 보여 주는 것으로 막는 것을 대신할 수 있는가. 정보 사용 감사는 무슨 일이 있었는지 알려 주지만 막지는 못하며, 주입·유출 방어는 보류되어 있습니다.
  • 시범 단계에서 둔 예외를 언제까지 유지할 것인가. 여러 계약의 기본 규칙 위에 시범 예외가 겹쳐 있고, 보안 강화 작업은 아직 정의되지 않았습니다.
  • 위임(Mandate)을 기존 권한(Grant)과 어떻게 연결할 것인가. 실제 동작에 반영하는 일은 미뤄져 있습니다.

판단과 조율

  • 작업 도중의 정정이 판단 모델에게 전달되지 않아, 낡은 계획대로 다시 맡기는 일이 생길 수 있습니다.
  • 주 AI 계열 안에서만 맡기는 결정은 처음 구상보다 크게 좁아졌고, 기록된 근거는 소유자 결정 하나입니다.
  • Codex와 Claude Code는 외부 연결과 스킬을 다루는 방식이 달라, 같은 수준으로 통제되지 않습니다.

기억

  • 확신도를 어떻게 표현할지 정해지지 않았습니다.
  • 잊기의 세 수준이 아직 서로 맞물리지 않았습니다.
  • 지금의 기억 저장소에는 유효 기간과 철회 시각이 기록되지 않습니다.

스킬과 연결

  • AI가 소유자를 위해 안전하게 새 스킬을 쓰는 장치는 아직 없습니다.
  • 가장 안전한 경로가 가장 덜 유능할 수 있습니다. 중간에 확인할 수 없는 연결에서는 무언가를 바꾸는 기능을 아예 열지 않아, 실제 일이 다른 경로로 돌아갑니다.
  • 서비스 회사가 직접 내놓은 공식 스킬을 먼저 쓴다는 전제가 실제로 성립하는지는 확인되지 않았습니다.

제품

  • 내 컴퓨터에 먼저 둔다는 것이 내 컴퓨터에서만 처리한다는 뜻은 아닙니다. 구독형 AI는 공급자의 서버에서 동작합니다.
  • 정직함과 겉으로 보이는 쓸모가 부딪칠 때가 있습니다. 상대가 받았다는 확인 없이는 “전달됨”이라고 말하지 않는 규칙 때문에 많은 공유가 “전달 불확실”로 끝날 수 있습니다.
  • 개발이 끝났다고 본 기능이 실제 사용에서 다르게 동작한 일이 여러 번 있었습니다. 시험 환경과 실제 사용 사이의 거리를 줄이는 방법은 아직 다듬는 중입니다.
