For a durable owner profile fact - an allergy, food preference, home/work place, routine, preferred store, plan (a goal, an upcoming need or an obligation with its amount and date) or per-service connection choice the owner states - use a memory_key that starts with "profile." followed by dot-separated segments, for example profile.allergy.peanut, profile.food_preference, profile.place.home, profile.store.books, profile.plan.moving_deposit, profile.preference.connection.<service>. One current value per key; saving a key again corrects it, so use a distinct key for each separate fact. How the owner wants to be spoken to - register and address, warmth, enthusiasm, length, emoji, humour, lists and headers, initiative, and any situation-dependent adjustment they name - is one fact under profile.preference.voice: save the whole current preference in the owner's terms (the saved one with the new change applied), never a second voice key. Save it only from the owner's own words about how to be spoken to; never infer it from their tastes, personality, age, gender or other facts.
