# #849 embedding arms on R1 v2

This is eval-only work on issue #849. No runtime code, fixture, paired-runner
implementation or existing recall tests are changed. The owner's chosen AI
performs the work; this measures a potential recall blocker without scripting
an owner task. Each step is committed separately: the frozen declaration before
the held-out run. Inference uses local files only.

## Dev selection declared before measurement

Selection is fixed before scoring: require zero dev traps, then maximise exact
case passes (all needed rows, zero traps and zero noise), then minimise noise
rows. Ties prefer smaller top_k, higher similarity floor, content-only passages,
no context, empty-only semantic admission, then alphabetical arm name. No
held-out outcome participates in selection.

The grid is top_k {1,2,3}, min_sim {0.78,0.80,0.82,0.84}, context {on,off},
passages {content,key+content}. The helper's spelling for key+content is
`key-content`. Hybrids try empty-only and unconditional vector admission;
RRF k=60 stays fixed. This gives 48 vector and 96 configurations for each of
two hybrid arms, 240 in total. The full grid is recorded in
[results/r1v2-dev-sweep.json](results/r1v2-dev-sweep.json).

V2 dev contains all 24 v1 cases, including the former v1 held-out cases already
seen by the spike. They are dev now and are allowed tuning inputs. Only dev
queries are embedded/scored by the new arms during this task; all 57 synthetic rows form the
shared corpus, with canonical eligibility applied before indexing and rechecked
at query time. Fresh v2 held-out retrieval is reserved for Claude's single
machine-locked run outside this sandbox. Reading the fixture definitions is
not a held-out measurement.

### Gate and attribution

**Fixture verdict under the pre-registered rule:** **no-go**. All three arms
have `preferred=false` in the combined gate. All have zero traps on both splits
and the same three common fixes, `h2-smoke`, `h2-swimming` and `h2-riddle`.
Each is a held-out paraphrase fix recovering a missed needed row against both
lexical baselines, so the common-needed-recovery requirement passes.

| Arm | Failed substantive rules | Combined preferred |
| --- | --- | --- |
| vector | No lost lexical control (`h2-context-lift`); no held-out regression | false |
| hybrid | No held-out regression | false |
| hybrid_lexical_context | No lost lexical control (`h2-context-lift`); no held-out regression | false |

**Fixture verdict:** `preferred_against_both` is consequently also false for
every arm. All three are preferred in the separate `lexical-context` and
`runtime` reports, but none against `lexical`. Substituting `runtime` for the
failing baseline after seeing held-out would be post-hoc and cannot produce a
go under the written rule. The dev loss `d-dated-current` is also retained;
it is not a held-out failure or lexical-control failure.

**Inference from 24 held-out fixture cases:** the two harm-control failures
(`h2-context-aquarium`, `h2-context-inkstone`) and hybrid_lexical_context's
noise-only lift failure also occur with model-free preceding-context retrieval,
including the shipped #860 path. For those failures, the pattern points to
added preceding context rather than an embedding-specific defect. This is an
observation on these cases, not causal proof or a general safety claim.
Vector's lift loss is different: context combined with top_k=1 cosine admission
returns only `n28` and drops needed `n29`. No model-free arm shows that loss.
The exact-case comparison labels vector versus the context baselines
unchanged-fail, which does not mean their returned rows or failures are equal.
Hybrid preserves the request-only lexical control but still fails both harm
controls. The ranking/bound interaction on #860 needs its own investigation.
The three shared paraphrase fixes remain an embedding gain over the measured
lexical references; this run does not compare all AI-written query phrasings
or establish improved owner answers.

## Runtime composition boundary

The supplied embedding environment imports `personal_agent.quickstart_store`
and `personal_agent.quickstart_service` successfully: no missing runtime package
was observed. Embedding factories do not import quickstart_service.

`hybrid_runtime` is resolvable but explicitly raises `NotImplementedError`:
`recall_arms.runtime` seeds jobs/messages on the supplied store on every call.
Composing it directly would violate this lane's **never write to the store**
requirement. Copying/seeding another store or replacing its brief path would
no longer be clean composition over the runner's canonical rows. The script
therefore measures the three read-only embedding arms and the exact runtime
arm separately, and produces a third report with runtime as baseline. The
runtime harness's synthetic job/message writes are its existing behaviour;
it does not mutate canonical Memory. `--runtime-python .venv/bin/python` can
run that baseline in a separate interpreter if a later environment needs it.

## Measurement semantics and reproduction

Set `STILL_E5_MODEL_DIR="$MODEL_DIR"` and optionally `STILL_E5_MODEL_FILE`
(default `onnx/model_O4.onnx`). Paths in committed artifacts are portable.
Use the supplied embedding interpreter as `$VENV`:

```sh
STILL_E5_MODEL_DIR="$MODEL_DIR" PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src:evals:. \
  "$VENV" -m evals.embedding_spike.r1v2_measure \
  --split dev --out-dir evals/embedding_spike/results
```

Claude's one held-out measurement, **under the shared machine lock**, is:

```sh
STILL_E5_MODEL_DIR="$MODEL_DIR" PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src:evals:. \
  "$VENV" -m evals.embedding_spike.r1v2_measure \
  --split all --out-dir evals/embedding_spike/results/r1v2-locked
```

Each arm runs once through the paired runner; the exact recorded candidate
observations feed all three baseline reports. Embedding calls also verify
identical ordered IDs and full ranks on a second uncached inference over the
same canonical store; only the first call's timings are reported. Synthetic
rows are never inserted into Memory. Build timings use actual passage encoding,
including tokenisation/pooling, and materialised float32 vector bytes, for the
fixture and deterministic unique 30–200 character Korean/English notes at
1k/10k scale. The corpus generator reads no case labels.

`recall@k` is micro needed-row recall: sum of needed refs in the first k unique
eligible ranked refs divided by total needed refs, separately per split and
kind, for k=1,3,5. Empty-needed cases contribute zero to both counts; an
all-empty group is null. Vector uses the full cosine list before min_sim and
top_k. Hybrid uses RRF over the exact lexical list and full cosine list before
min_sim/top_k/empty-only admission. This diagnostic rank is deliberately
separate from the returned, cut-off list scored for preference. Baselines
expose their returned order, with no extra experimental cutoff.

The combined gate consumes the two lexical reports, requires each runner
verdict to be preferred, verifies zero traps on both splits/every run, no lost
lexical control and no held-out regression, and intersects the fixed case IDs.
At least one common fixed ID must increase needed-hit count against **each**
baseline. Noise removal alone cannot certify embedding recall. Dev-only
reports omit held-out tables and defer all preference verdicts.

Costs are local operating observations: process-cold load (fresh subprocess,
OS file cache not flushed), main-process first load, cached acquisition,
query-embedding/retrieval median and nearest-rank p95, index builds, model
file/directory bytes, process peak RSS and load averages before/after. Retrieval
excludes query embedding but includes canonical checks, lexical search and
fusion. No latency budget or production-quality claim follows from this small
fixture or a contended host. Python socket guards cover the main process and
cold/runtime workers; attempted connections must be zero. These guards do not
prove absence of native traffic. ORT telemetry is disabled after import;
its native import-time warning can still appear.
