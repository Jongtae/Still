Status: implementation and model-free qualification only. No v3 model,
embedding, live CLI or held-out candidate observation has been made here.
The v3 fixture, generator and fixture tests are owned separately and unchanged
by this lane. The caller's approved `/3` loader allowlist entry is retained.

## Arms and evidence

| Arm | Definition |
|---|---|
| `lexical` | Unchanged request-only MemoryService search. |
| `lexical-context` | Unchanged context-first lexical reference. |
| `runtime` | Unchanged request-only product worker snapshot matches. |
| `prefix-lexical` | Request-only search, with Hangul expansion parsed from `quickstart_store.fts_prefix_expression`; store limits/date/eligibility remain authoritative. Model-free control, not an embedding candidate. |
| `vector` | Existing pinned cosine index with request-only queries and content passages. |

| plan-query | Actual qualified plan's `recall_query`, replayed through the shared worker snapshot. Three samples; compare with lexical and request-only runtime. |

Every arm measured through `recall_report.run_arm` also receives a **separate
snapshot diagnostic**, never a verdict input. `r1v3_snapshot.measure` injects
the arm's ordered, current, holding profile rows into one service instance's
search seam, then calls the real `MemoryService.profile_snapshot` with default
bounds. It counts all needed rows shown (including unmatched fill), omissions,
and the real request-only snapshot reference. JSON retains cases and totals
per split, kind and leading note facet; Markdown adds a diagnostic table.
Tests establish that the v2 report apart from this diagnostic is byte-identical.
Old arm retrieval, scoring and gate semantics are unchanged.

## Selection and freeze

`r1v3_measure --dev-sweep` indexes all fixture rows but removes held-out cases
before constructing any arm, lookup or query inference. The grid has 66
candidates: each of `vector` and `hybrid`, `top_k` in `{1,2,3}`, `min_sim`
from `0.70` through `0.90` inclusive in steps of `0.02`.

Predeclared order: reject candidates with dev trap hits; maximize exact dev
passes, then minimize noise, then choose higher `min_sim`. Remaining ties use
smaller `top_k`, then arm name. Freeze one selection per arm and a primary by
the same order. Context remains off, passage form remains content, and the
hybrid admission/RRF rules above are fixed rather than swept.

The output `r1v3-frozen.json` binds the complete source fixture digest, dev IDs,
model revision/file/tokenizer digests, grid, selection rule, records, selected
parameters and primary. A separate owner-controlled integration must commit
that JSON before a locked run; this task makes no commit. `--frozen` refuses
untracked, staged or unstaged changes relative to HEAD, outside-repository
paths, mismatched fixture/model/protocol, and selections outside the grid or
ordering. These checks finish before model loading or any held-out arm.

## Locked gate and decision mapping

Only `--frozen <committed-clean.json> --split all` enables the later locked
measurement. It runs each arm once, reuses identical candidate observations
for reports against **lexical, lexical-context and runtime**, and records
snapshot diagnostics and micro recall@1/3/5. The imported socket guard denies
Python connections and DNS; it does not establish native-network containment.
The existing pinned local-only encoder remains responsible for CPU inference
and provenance. No model, package, index or runtime is installed by this lane.

The three-baseline gate requires preference against each baseline, zero trap
hits on both splits/every run, no lexical-control loss, no held-out regression,
and at least one **common fixed held-out case with increased needed hits
against every baseline**. Noise-only fixes cannot pass. Dev-only reports have
no preference verdict. Fixture #827 held-out discipline remains: one locked
evaluation with preregistered sampling, and a held-out-motivated change moves
the case to dev and requires a replacement held-out case.

The frozen mapping tests #403's **miss that phrasing cannot fix** explicitly.
Evaluate A, then B, then C; stop at the first matching row.

| Later observation (in order) | Decision text |
|---|---|
| **A.** An embedding arm passes the three-baseline gate (lexical, lexical-context, request-only runtime), and at least one of its common fixed held-out cases is **not fixed by plan-query** under the R1 3-sample majority/uncertainty rule; uncertain counts as not fixed by plan-query. | `reopen step 2 under #849 (cost limits still apply)` |
| **B.** Else, plan-query is preferred against lexical under the R1 rule (zero traps, no lost lexical control, at least one held-out fix that is not uncertain, no held-out regression), or an embedding arm passes but every one of its common fixes is also fixed by plan-query. | `#403 met by step 1` |
| **C.** Else. | `#403 residual misses recorded; step 2 not reopened` |

The plan-query vs embedding comparison uses the **per-case R1 majority
outcomes** from the plan harness score report and the locked embedding reports,
matched by case ID. The snapshot diagnostic (`needed_in_snapshot`),
`prefix-lexical`, and the plan direct-reply / needed-in-plan-profile facts are
reported but are not inputs to A/B/C.

## Live-plan harness

`scratch-403/r1v3-live.py` copies the original `883-live-check.py` while keeping
its guard, qualification blockers, recorder transport, no-retry cap and command
preview bodies structurally identical (AST equality checked). Only the exact
existing store/runtime_root binding allowance is available. Fake mode never
constructs a live engine; qualification remains blocked. Recordings retain the
real selector, direct-reply flag, whether every needed row was in the plan's
request-only snapshot, worker snapshot diagnostic, token metadata and per-call
wall time. Reported token totals distinguish missing usage from zero.

Scoring uses the unchanged R1 majority/spread code with three replay runs:
spread larger than the difference from baseline marks a fix uncertain. Any
observed trap still overrides majority. The old per-run details remain for
inspection; their unions are not the R1 majority verdict. The cap stops before
dispatch beyond `--max-calls`; it is not a cap on unobservable CLI-internal work.

## Existing Solutions Review

**Adopt:** installed stdlib argparse, JSON, tempfile, unittest.mock and git's
`ls-files`/`diff HEAD` interface; SQLite FTS5 via the product's quoted-prefix
helper; pinned official ORT/tokenizers APIs and existing numpy cosine/RRF.
Their required behavior is already demonstrated in the local implementation
and tests. No acquisition, new dependency or release check was performed offline.

**Adapt:** existing `MemoryService.profile_snapshot`, `recall_report` diagnostic
attachments, `r1v2.make_retriever`, `instrument`, `recall_at_k`, `dev_report`,
`_CachedEmbedder`, `_offline_guard`, the existing combined gate with an optional
baseline tuple (its v2 default is unchanged), and the original scratch harness. These
seams already follow the reviewed external APIs; bounds, rankers, eligibility
and transport/identity guards are reused rather than copied into new policy.

**Build:** bounded experiment glue for the exact grid/freeze binding,
three-reference common-needed-recovery gate and observation aggregation. A
general evaluator/vector database cannot supply these Still-specific scorer
and canonical-state contracts. No replacement framework or persisted vector
store is needed. Existing PSF stdlib, MIT ORT/model, Apache-2.0 tokenizers and
permissive numpy provenance is reused under the repository's AGPL code; no new
licence, deployment, egress, secret or authority surface is introduced. Native
dependency provenance and supply-chain limitations from R1.md remain open for
any eventual product adoption.
