## Tuning and frozen parameters

The fixture is `recall-pairs/1`: 25 synthetic rows, 14 dev cases and 10 held-out cases. Fixture digest: `720e8939da261a61f702be74bad195c2fa9c6f00658733ac15fbdf2f3ad89cda`.

The fixture and tests were read as requested, including held-out definitions, but no held-out retrieval or score was run during tuning. One dev-only fp32 sweep evaluated **144 configurations: 48 vector and 96 hybrid**. All canonical eligible rows, including rows serving held-out queries, are the shared retrieval corpus; only the 14 dev query cases supplied tuning labels. The entire grid, envelopes and judgments are in [r1-dev-sweep.json](results/r1-dev-sweep.json).

Grid: `top_k ∈ {1,2}`, `min_sim ∈ {0.78,0.80,0.82,0.84,0.86,0.88}`, context on/off, content versus `memory_key + ' ' + content`. Hybrid also tries semantic additions to any lexical list versus additions only when lexical search is empty. RRF `k=60` was fixed in advance; there is no extra fused-score cutoff.

Selection order, implemented before scoring: minimise trap hits, minimise lost lexical-control cases, maximise exact case passes, minimise noise, maximise needed hits. Ties prefer smaller top_k, higher similarity floor, content-only passages, no context, and empty-only semantic admission, in that order. Vector and hybrid were selected separately and chose the same vector settings.

**Frozen before any held-out query was embedded or scored:** `top_k=1`, `min_sim=0.82`, `use_context=True`, `passage_form='content'`. Hybrid adds `k=60`, `vector_only_when_empty=True`. Every lexical result is retained; only a cosine-qualified top-1 vector result may be added when the lexical list is empty. RRF orders retained IDs, and no total-result cap discards a lexical hit. Context means the preceding turn plus a space plus the query, when a preceding turn exists.

## Canonical boundary and verification

The index reads current owner rows with `QuickStore.memories(owner_id=..., holding_on=today)` through the existing paginated API. Every query repeats that canonical read and discards any cached ID absent from it or whose passage text changed. Hybrid rechecks retained IDs with `QuickStore.memory` as well. Expiry is inclusive on `today`. New/replaced rows require rebuilding the disposable index; stale cached rows cannot resurrect deleted, forgotten, superseded, corrected, expired, other-owner or changed-content entries. No retriever writes to the store, creates a vector table, or uses fixture answer labels.

`recall_pairs.run` checks the Memory digest around every query. The CLI also checks it around factory construction and the whole arm. [r1-validation.json](results/r1-validation.json) records focused negative checks for mismatched model/tokenizer pins before heavy imports, module imports without installed packages, owner/state/expiry filtering, inclusive last day, and invalidation after forgetting, supersession, expiry, deletion and content mutation. The real final runs retain unchanged Memory digests. Synthetic mutation checks use a fake embedder solely to isolate the canonical-cache boundary; retrieval scores use the real pinned models.

`PYTHONPATH=src .venv/bin/python -m pytest -q tests/test_recall_pairs.py` → **44 passed in 39.89s**. Only the permitted eval files and outputs are added; no commit is made.

Offline controls: HF_HUB_OFFLINE=1, HF_HUB_DISABLE_TELEMETRY=1 and HF_HUB_DISABLE_IMPLICIT_TOKEN=1 are set before tokenizers import; both file hashes are checked before ORT/tokenizers loading; ORT telemetry is disabled through its API and provider fallback is disabled. Each final run patches Python `socket.socket.connect`, `connect_ex` and `getaddrinfo` to raise and observed **zero Python socket attempts**. Models and tokenizer are loaded solely from local paths. ORT's macOS native initialisation still emitted a telemetry-device-ID warning and native NetworkStorageDB cache warnings before/around telemetry disabling. The Python socket guard does not intercept native networking; there was no packet capture or OS-level network audit. This evidence establishes guarded local inference, not an audited absence of all native telemetry traffic.

## Integration entry point

```python
from evals.embedding_spike.r1_arm import hybrid, FROZEN_HYBRID
from evals.embedding_spike.embed import Embedder, MODEL_PINS, TOKENIZER_PIN

embedder = Embedder(
    model_dir,
    model_file='onnx/model.onnx',
    model_sha256=MODEL_PINS['onnx/model.onnx'],
    tokenizer_sha256=TOKENIZER_PIN,

# store and data are caller-owned; seed first with recall_pairs.seed(store, data).

# retriever(query, context='') -> list[str] memory IDs
result = recall_pairs.run(retriever, data['cases'], refs)
```

### Which fixes are attributable to embeddings?

- **Dev, embeddings without extra context:** `d-para-focus` and `d-para-posture` are fixed versus `lexical_context` by both context-free arms, both original embedding arms, and `hybrid_over_lexical_context`. These two cases have no preceding context, so changing the context switch cannot explain the gain. All these arms also regress `d-expired-date` by adding unrelated eligible noise.
- **Held-out, post-hoc, embeddings without extra context:** only vector replacement fixes `h-correction` versus `lexical_context`; both contextual and context-free vector arms return only `r22`, removing the lexical distractor `r6`. Neither hybrid fixes it because the frozen rule retains every lexical hit. This is a precision fix, not a new needed-row recall gain.
- **Follow-ups are not an embedding-specific gain:** `d-follow` and `h-follow` are already passes under `lexical_context`. No embedding arm fixes either versus that reference. In the context-free vector/hybrid arms, held-out `h-follow` returns unrelated `r2`: needed `r18` has rank 2 / cosine 0.828585, above the floor but outside top-1. With context it becomes rank 1 / 0.874102. Lexical context retrieves it directly, so embeddings are unnecessary for this observed fix.
- **No embedding-specific held-out hybrid fix:** neither original hybrid nor `hybrid_over_lexical_context` fixes any held-out case versus lexical context. The vector-only correction fix does not justify preference either: contextual vector drops the needed cross-language row, yielding 4/6 recall versus lexical context's 5/6. The context-free vector arm also misses the follow-up, yielding 3/6 and an additional noise row.
