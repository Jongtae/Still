# 연구 기록: 기억 구조와 밤사이 정리(dream) 실험 (2026-10-22 ~ 11-05)

이 문서는 #205 D2, #217, #402, #416, #442, #495, #496, #638의 근거 기록이다. 구현을 활성화하지 않는다. 채택된 규칙은 [Secretary Agency Contract](../secretary-agency-contract.en.md)에 있다.

**공개 원칙.** 이 문서는 집계 숫자, 방법과 결론만 담는다. 소유자의 개인 정보는 적지 않는다. 다음은 소유자의 메시지, 답변이나 기억을 담고 있거나 그것에서 파생됐으므로 소유자 Mac에만 두고 이 저장소에 올리지 않는다.

- 내보낸 이력
- 시험 요청과 정답 세트
- 각 방식의 맥락과 dream 출력
- 판정 원문
- 검색어 로그
- 댓글 초안

실험은 모두 소유자 승인을 받아 로컬에서 읽기 전용 내보내기로 실행했다.

**증거 등급.** 모든 결과는 실제 이력을 오프라인으로 재생하고 모델이 판정한 것이다. 실제 사용에서 관찰한 결과가 아니다. 정답 세트는 아직 소유자가 검증하지 않았다.

## 1. 공통 방법

- **시험 요청:** 10/12~10/22 요청 중 41건이다. 기억이 필요한 요청 33건, 대조 8건이다. 각 요청은 그날 시작 시점의 기억 상태로 비교했다.
- **정답:** 요청일 이전 소유자 원문에서, 그 요청을 처리할 때 염두에 둬야 할 사실 239개(필수 66개)를 뽑았다. 함정 169개도 함께 표시했다. 함정은 현재처럼 보이면 AI를 오도하는 지난 진술이다. 표시는 Claude Opus가 했다.
- **판정:** 판정 모델은 각 방식이 만든 맥락을 이름을 가리고 무작위 순서로 읽는다. 그리고 정답 사실마다 전달(yes / partial / no), 현재처럼 노출된 함정, 그 밖의 오해 소지를 표시한다.
- **지표:**

| 지표 | 뜻 |
|---|---|
| needed | 전달된 필요 사실의 비율 |
| essential | 그중 필수 사실의 비율 |
| traps | 지난 정보를 현재처럼 노출한 수 |
| misleading | 그 밖에 오해 소지가 있는 진술 수 |
| win/loss/tie | 요청별 맞대결 결과 |

- **잡음:** 같은 코드를 다시 재생하면 needed가 약 10점 흔들렸다. traps는 같은 방식에서도 판정마다 약 ±3 흔들렸다. 한 번의 실행으로 작은 차이를 결론짓지 않는다.

## 2. M1~M5: 기억 쓰기 구조 비교 (2026-10-22~23, #205 D2)

라이브 Still의 Work 654건과 Memory 82행을 내보내 썼다. M3~M5는 Still 기억 정리 모델(`gpt-5.6-luna`)로 날짜 단위로 재생했다. 판정은 Claude Opus가 했다. 필요 사실이 있는 요청 40건 기준이다.

| 방식 | 내용 | needed | essential | traps | misleading | 평균 크기 |
|---|---|---|---|---|---|---|
| M1 | 당시 방식: key 순서 1,200자 스냅샷 | 24% | 20% | 8 | 4 | 1,248자 |
| M2 | key 행 전부, 자르지 않음(#217) | 52% | 49% | 21 | 43 | 5,880자 |
| M3 | key 방식 + 정리 AI가 전체 프로필을 봄 | 35% | 21% | 19 | 8 | 2,177자 |
| M4 | 문서 하나를 매일 통째로 재작성 | 58% | 53% | 2 | 6 | 2,793자 |
| M5 | 덧붙이기 + 무효 처리 | 54% | 48% | 11 | 2 | 2,535자 |

맞대결(이김/짐/같음)은 M4 대 M5가 19/11/10, M4 대 M3가 34/1/5, M5 대 M3가 32/1/7이었다.

결론:

- 당시 손실의 절반은 1,200자 절단에서 왔다. 다만 절단만 풀면 지난 정보와 요청문 행도 그대로 노출된다.
- key 방식은 전체 시야를 줘도 약했다.
- 쓰기 구조는 덮어쓰기 대신 덧붙이기 + 무효 처리를 택했다.
- 239개 중 46개는 다섯 방식 모두 전달하지 못했다. 다음 후보로 "작은 상시 핵심 + 요청 시점의 원문 이력 회수"를 남겼다.

## 3. m7 계열: 밤사이 정리(dream) 도입 (2026-10-30, #402, #416, #420)

Still의 실제 dream 프롬프트, 스키마와 검사(`validate_dream`, `validate_review`)를 밤마다 재생했다. dream이 쓴 것은 실제 기억 위에 덧씌웠다. 판정은 Claude Opus가 했다.

| 실행 | 방식 | needed | essential | traps | misleading | 맞대결(대 운영) |
|---|---|---|---|---|---|---|
| m7d | 운영(dream 없음) | 54.6% | 47.7% | 10 | 12 | |
| | dream, 정리 모델(luna) | 60.0% | 56.8% | 13 | 14 | 16/2/22 |
| | dream, 엔진 최상위 모델 | 62.3% | 58.3% | 8 | 12 | 23/1/16 |
| m7e | 운영(dream 없음) | 55.2% | 50.0% | 12 | 20 | |
| | dream 한 번 | 61.9% | 59.1% | 10 | 16 | 21/3/16 |
| | dream 두 번(먼저 모으고 그다음 정리) | 68.8% | 64.4% | 9 | 3 | 28/0/12 |

결론:

- dream은 엔진의 최상위 모델로 돌린다(#420). 모델 이름은 고정하지 않는다.
- 사실을 먼저 모으고 그다음 정리하는 두 단계로 돌린다(#416). 이 방식에서 오해 소지가 20에서 3으로 줄었다.
- 최근 하루 기록을 요청 맥락에 넣으면(#442) needed가 75~77%로 올랐다(m9, m10의 기준선). m7f 보고서는 집계 단계 오류로 완성되지 않았고, 그 수치는 m9와 m10에서 다시 쟀다.
- 이 단계에서 남은 놓침은 모두 이전 날에서 나왔다.

## 4. m8: dream이 쓴 것의 정확도 감사 (2026-10-31, #495)

dream이 저장한 사실, 끝낸 사실, 새 메모 항목, 하루 기록 줄을 하나하나 그날 밤의 요청과 대조했다. 판정은 Codex `gpt-6.1-sol`(medium)이 했다. 각 칸은 정확 비율, 그리고 틀림 / 지나친 일반화 / 소유자 말 아님 / 나중에 오도한 수다.

| 대상 | m8: 당시 main | m8z: 출처 기록(#495) | m8aa: + 이전 날 기록으로 메모 |
|---|---|---|---|
| 사실 | 46개, 93% (2 / 0 / 1 / 3) | 47개, 91% (2 / 2 / 0 / 4) | 57개, 82% (6 / 3 / 1 / 10) |
| 끝낸 사실 | 15개, 73% (4 / 0 / 0 / 2) | 14개, 86% (2 / 0 / 0 / 2) | 17개, 59% (7 / 0 / 0 / 5) |
| 메모 항목 | 12개, 17% (1 / 3 / 6 / 6) | 0개 | 6개, 0% (0 / 3 / 3 / 6) |
| 하루 기록 줄 | 133개, 92% | 132개, 92% | 135개, 93% |
| 전체 | 206개, 87% | 193개, 91% | 215개, 85% |

결론:

- 사실마다 근거(`owner_said` / `inferred`)와 인용을 남기게 했다(#495). 그 뒤로 어시스턴트가 한 말이 소유자의 말로 저장되지 않는다.
- 이틀 규칙 때문에 dream의 메모는 사실상 꺼졌다.
- 이전 날의 하루 기록을 근거로 메모를 쓰게 하면(m8aa) 메모가 지나치게 일반화되고, 사실과 끝내기의 정확도도 떨어졌다.

## 5. m9, m10: 출처 기록과 이전 날 기록 (2026-10-31, #495, #496)

판정은 Claude Opus가 했다.

| 실행 | 방식 | needed | essential | traps | misleading | 맞대결 |
|---|---|---|---|---|---|---|
| m9 | main | 76.6% | 73.5% | 9 | 6 | |
| | main + 출처 기록 | 74.5% | 77.3% | 8 | 6 | 4/10/26 (대 main) |
| m10 | 출처 기록 전 | 76.4% | 74.2% | 8 | 6 | |
| | 출처 기록 | 75.1% | 78.8% | 8 | 8 | 5/10/25 (대 기록 전) |

결론:

- 출처 기록은 needed를 거의 바꾸지 않았다. 대신 m8에서 본 대로 저장의 정확도를 지킨다.
- 이전 날 기록 방식(#496 첫 시도)은 needed가 조금 올랐다. 그러나 traps가 늘고 메모가 지나치게 일반화돼서 머지하지 않았다.

## 6. 실제 사용 점검 (2026-10-31 ~ 11-05)

일주일 동안 실제로 써 본 뒤 dream이 쓴 기억을 소유자가 되돌린 비율을 재기로 했다. 5일 동안 결과는 다음과 같았다.

- dream 실행 3번, dream이 저장한 사실 5개와 하루 기록 2개.
- 그중 되돌리거나 고친 것은 0개.
- dream이 쓴 메모 버전은 0개. 같은 기간 개별 작업 돌아보기(self-review)는 메모 버전 2개를 썼다.

이 규모로는 되돌린 비율로 판단할 수 없었다. 게다가 dream은 조용히 정리하고(#425) 관련된 요청이 와야 드러나므로, 되돌리지 않았다고 해서 맞았다는 뜻도 아니다. 그래서 #496은 재생 실험으로 판단하기로 했다.

같은 점검에서, 2026-10-01 이후 작업 695건 가운데 36일 중 33일에 관찰된 실패가 있었다. 고침이 44건, 실패가 18건, 부분 완료가 201건이었다.

## 7. m11: 관찰된 실패에서 배우는 메모 (2026-11-05, #496 새 방식)

dream이 각 요청의 결과를 보게 했다. 결과는 완료, 부분 완료, 실패, 고쳐 들으심, 다시 시키심 중 하나이고 작업 상태와 연결 기록으로만 정한다. 이전 7일의 실패도 최대 12개까지 메모의 근거로만 읽는다. 메모는 기존 규칙 또는 "서로 다른 이틀의 실패 두 건, 그중 하나는 오늘 밤 것"으로 저장된다.

- **재생:** 2026-10-01 ~ 11-04, 현재 방식(Z)과 새 방식(AB) 각각 밤 33번. dream은 Codex CLI 최상위 모델로 돌렸다(운영과 같다).
- **판정:** Codex `gpt-6.1-sol`(high). 이전 실행의 Claude 판정과는 숫자를 직접 비교할 수 없다.

메모:

| 방식 | dream | 저장된 메모 버전 | 추가 항목 | 근거 있음 | 지나친 일반화 | 근거 없음 | 중복 | 이후 7일의 실패를 다룬 수 |
|---|---|---|---|---|---|---|---|---|
| Z | 33 | 0 (제안 8번이 모두 이틀 규칙에 걸림) | 0 | | | | | |
| AB | 33 | 4 (실패 규칙 3번, 기존 규칙 1번) | 4 | 100% | 0 | 0 | 0 | 2 (항목 1개) |

사실 회귀 확인(시험 요청 41건):

| 방식 | needed | essential | traps | misleading | 평균 크기 |
|---|---|---|---|---|---|
| Z | 63.8% | 59.1% | 12 | 0 | 5,851자 |
| AB | 66.1% | 60.6% | 13 | 1 | 6,175자 |

맞대결은 AB가 10건 이기고 1건 지고 29건 같았다.

결론: 새 방식은 사실 품질을 떨어뜨리지 않고 dream의 메모를 다시 켰다. 그래서 #641로 머지했다. 다만 실행이 한 번이고, 메모 표본이 4개이며, dream과 판정이 같은 모델 계열이다. 실제 사용에서 dream이 쓴 메모를 소유자가 지우거나 고치는지 지켜봐야 한다.

## 8. 남은 한계

- 정답 표시는 Claude Opus가 했고 소유자 검증 전이다. m11은 dream과 판정이 같은 Codex 계열이다.
- 재생은 날짜 단위 근사이고, 알림, 예산, 일시정지 같은 운영 조건을 다시 만들지 않는다.
- 측정한 것은 필요한 기억이 AI 앞에 놓였는지와, dream이 쓴 것이 근거에 맞는지다. 그 결과 답의 품질이 나아졌는지는 측정하지 않았다.
- 시험 요청은 41건이다. 작은 차이는 잡음 범위 안이다.
