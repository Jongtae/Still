# 4. 판단과 실행

[주제별 목차](README.md) · 개념 해설, 현재 도구 인터페이스의 대체 명세가 아님

## 문제: 요청이 늘 때마다 프로그램을 추가해야 하는가

사용자는 기능 이름과 정해진 문장만으로 요청하지 않는다. 표현과 상황이 바뀔 때마다 코드를 추가한다면 지원 시나리오가 늘어날수록 규칙의 조합도 늘어난다. 반대로 모든 결정을 모델에게 맡기면 정확해야 할 권한과 외부 실행의 상태까지 추론에 의존하게 된다.

Still이 택한 구분은 **AI가 일을 하고 의미를 판단하며, Still은 상태와 정확한 실행 경계를 유지한다**는 것이다. [개발 헌법 C16](../development-constitution.en.md)의 'AI is the engine'은 코드가 아무 역할도 하지 않는다는 말이 아니다. 특정 요청의 해결 절차를 핵심 코드에 하드코딩하지 말라는 원칙이다.

## 판단·권한·실행·결과는 서로 다르다

| 역할 | 다루는 질문 |
| --- | --- |
| 의미 판단 | 사용자가 무엇을 원하며 어떤 맥락·역할·다음 행동이 적절한가? |
| 권한 집행 | 이 요청의 정확한 자원·행동·범위가 현재 허용되는가? |
| 실행 | 선택된 AI와 도구가 실제로 무엇을 시도하고 관찰했는가? |
| 결과 평가 | 목표가 충족되었는가, 무엇이 부분 완료·실패·미확인인가? |

[Decision Layer](../decision-layer.en.md)는 의미 판단과 조정을 다루고, [Execution 계약](../assistant-execution-contract.en.md)은 실행과 결과의 경계를 다룬다. 목표가 충족되었다는 모델 판단이 외부 효과를 사실로 만들어 주지는 않는다. 결제 승인, 비밀 보호, 요청 재실행 방지, 정확한 승인 대상의 결합과 같은 불변 조건은 별도로 집행한다.

## 계획은 고정된 대본이 아니라 수정 가능한 지시다

판단 계층은 이미 정책상 사용할 수 있는 실행기를 선택하고 지시서를 구성하며, 결과가 부족하면 제한된 범위에서 다시 계획할 수 있다. 현재 Decision 계약의 도구 부분집합 제거 보완처럼 인터페이스는 바뀔 수 있으므로, 이 장에 오래된 필드 정의를 복사하지 않는다.

사용자가 도중에 조건을 바꾸면 실행 중인 작업뿐 아니라 이후의 계획과 결과 판단에도 그 수정이 전달되어야 한다. 실제로 전달할 수 없는 실행기라면 그 한계를 밝혀야 한다. 재시도 역시 목표를 해결하기 위한 판단이지, 미확인 외부 효과를 안전하게 반복해도 된다는 허가가 아니다.

## 전문성은 콘텐츠로, 권한은 실행 경계에

스킬은 조사 방법, 분야의 용어, 확인해야 할 항목과 보고 기준을 제공할 수 있다. 실행 AI가 그것을 읽고 적용한다. 스킬 이름이나 특정 사이트를 Still 핵심 코드의 분기 조건으로 만드는 것과는 다르다.

[Connection and Delegation](../connection-delegation-contract.en.md)은 어떤 연결과 실행 수단을 어떻게 사용할지, 어느 수준까지 Still이 통제하는지 구분한다. 연결 설정이 있다고 실제 준비 상태가 검증된 것은 아니며, 외부 실행기 내부의 모든 행동을 Still이 통제한다고 가정하지 않는다. 연결의 발견·확인·사용·실행 결과는 서로 다른 사실이다.

새 작업을 이해할 수 있다는 것과 필요한 도구가 있다는 것도 다르다. 지원되지 않는 행동은 우회하여 완료했다고 말할 일이 아니라, 부족한 능력과 가능한 다음 경로를 설명할 일이다.

## 속도와 품질의 긴장

판단 호출을 줄이면 빠를 수 있지만, 정정 반영이나 결과 검증을 잃을 수 있다. 따라서 응답 시간을 줄이는 문제를 '짧아 보이는 질문은 검증하지 않는다'는 규칙으로 단순화하지 않는다. 같은 조건에서 실행 경로, 사용자가 받는 첫 유효한 답, 실제 결과의 차이를 측정해야 한다. 이 장은 특정 지연 목표를 달성했다거나 특정 모델이 더 빠르다고 주장하지 않는다.

## 남아 있는 질문

어디까지를 실행 AI의 자율성에 맡기고 어디에서 별도의 판단이 도움이 되는가? 동일한 계약을 따르는 실행기 사이에도 실제 도구 사용과 중간 개입 능력이 얼마나 다른가? 실패 후 재계획이 유용한지 반복만 늘리는지 어떻게 구분할 것인가?

설계 판단은 [C16](../development-constitution.en.md), [Decision](../decision-layer.en.md), [Execution](../assistant-execution-contract.en.md), [Connection and Delegation](../connection-delegation-contract.en.md)을 따른다. 성공한 예시 하나나 도구 선언만으로 실행 경로 전체가 검증되었다고 보지 않는다.
