# 1. 소유와 연속성

[주제별 목차](README.md) · [다음: 온톨로지와 역할](ontology-and-roles.ko.md)

## AI를 바꾸어도 이어져야 하는 것

Still은 가장 뛰어난 모델을 직접 소유하려는 프로젝트가 아니다. 모델을 빌려 쓰더라도, 사용자를 이해하는 데 쌓인 정보와 아직 끝나지 않은 일은 사용자가 관리할 수 있어야 한다는 문제의식에서 출발한다. [VISION](../VISION.md)은 이를 한 사람을 오래 돕는 에이전트의 조건으로 설명한다.

모델 교체 뒤에도 대화 기록을 읽을 수 있다는 것만으로는 충분하지 않다. 어떤 선호가 지금도 유효한지, 무엇을 승인받았는지, 어떤 결과가 확인되었는지 알아야 같은 일을 이어갈 수 있다. Still이 유지하려는 연속성은 **이전 대화를 재현하는 능력보다, 이전 상황을 바탕으로 다음 행동을 결정할 수 있는 상태**에 가깝다.

| 사용자에게 남아야 할 상태 | 교체할 수 있어야 할 수단 |
| --- | --- |
| 출처와 정정 이력이 있는 기억과 맥락 | 추론과 생성을 담당하는 모델 |
| 목표, 진행 중인 작업, 남은 의무 | 모델 API, 구독형 AI의 실행 도구, 위임받은 에이전트 |
| 접근 권한, 승인 범위, 취소 상태 | 서비스를 연결하고 호출하는 도구 |
| 결과물과 실제 실행 기록 | 개별 기능이나 스킬의 공급자 |

이 구분은 [아키텍처 기준 문서](../personal-agentos-architecture.en.md)의 책임 구분을 풀어 쓴 것이다. 각 행이 별도의 데이터베이스를 뜻하지는 않는다.

## 데이터 분리와 업무 연속성의 차이

비교할 만한 선행 규격은 Solid다. Solid Protocol 0.11.0은 애플리케이션이 외부에 저장된 데이터에 권한을 확인하고 상호운용 가능한 방식으로 접근하는 규격을 묶는다. 사용자가 데이터와 애플리케이션을 선택할 수 있게 한다는 방향은 Still의 문제의식과 닿아 있다. 다만 이 판본은 W3C 표준이 아니라 커뮤니티 그룹 초안이다. [R1](references.md#r1)

Still이 다루려는 문제는 여기서 더 구체적이다. 데이터를 읽는 방법뿐 아니라, **어떤 일을 어디까지 수행했고 다음에 무엇을 해야 하는지**도 모델과 분리해 남기려 한다. Solid의 설계는 비교 대상이지, Still이 Solid를 구현했다거나 작업 이전을 검증했다는 근거가 아니다.

이 관점에서 이전 가능성은 세 단계로 나누어 살펴볼 수 있다. 이는 Still을 검토하기 위한 구분이다.

| 단계 | 확인할 질문 |
| --- | --- |
| 데이터 이전 | 기록과 결과물을 꺼내 다른 환경에서 읽을 수 있는가? |
| 의미 보존 | 출처·시간·현재 유효성·권한 범위가 같은 뜻으로 해석되는가? |
| 업무 재개 | 새 실행 수단이 필요한 도구와 인증을 갖추고 남은 일을 이어갈 수 있는가? |

첫 단계의 성공이 나머지 두 단계를 보장하지는 않는다. 같은 기록을 읽더라도 모델마다 해석과 도구 사용 능력이 다를 수 있다.

## 연속성은 이전 승인을 복제하지 않는다

다음은 가상의 설계 사례다. 사용자가 AI를 바꾼 뒤 “아까 준비한 것에서 수량만 바꿔줘”라고 요청한다. 대상과 준비 상태는 이어받아야 하지만, 변경된 수량까지 이전 승인이 허용하는지는 별도로 확인해야 한다.

같은 이유로 작업을 이어간다고 해서 이미 실행한 행동을 다시 수행해서는 안 된다. 외부 서비스가 요청을 처리했는지 알 수 없다면, 기록을 바탕으로 결과를 확인하거나 불확실성을 알리는 것이 먼저다. 업무의 연속성과 권한·결과의 정확성은 함께 유지되어야 한다. 해당 규칙은 [실행 기준 문서](../assistant-execution-contract.en.md)에 있다.

## 소유는 저장 위치보다 넓은 개념이다

파일이 로컬에 있어도 사용자가 내용을 확인하거나 고칠 수 없다면 통제권은 제한적이다. Still의 [사용자 통제 기준](../owner-control-contract.en.md)은 저장된 정보 확인, 접근 범위 선택, 외부 전달 확인, 권한 철회, 결과 보존과 이전을 요구사항으로 다룬다.

반대로 로컬 설치가 모든 처리를 로컬에서 수행한다는 뜻도 아니다. 외부 AI를 선택하면 요청에 쓰이는 맥락이 그 공급자에게 전달될 수 있다. 원격 서비스가 보관하는 사본까지 Still이 직접 통제하는 것은 아니다. 따라서 소유를 설명할 때는 저장 위치와 함께 실제로 가능한 확인·변경·철회의 범위도 밝혀야 한다.

## 무엇을 확인해야 하는가

이 설계의 가치는 모델 교체, 인증 만료, 실행 중단 뒤에 드러난다. 같은 일을 다시 설명하는 부담이 줄어드는지, 이전 권한이 잘못 적용되지 않는지, 결과물이 남아 있는지 확인해야 한다. 사용자가 이런 연속성을 얻기 위해 시스템 관리에 더 많은 시간을 쓰게 된다면 설계의 목적을 다시 검토해야 한다.
