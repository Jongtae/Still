# 3. 기억과 학습

[주제별 목차](README.md) · [이전: 온톨로지와 역할](ontology-and-roles.ko.md) · [다음: 판단과 실행](judgment-and-execution.ko.md)

## 저장한 정보가 다음 요청에 도움이 되려면

대화 전체를 보관해도 필요한 내용을 찾지 못할 수 있다. 반대로 짧은 프로필은 중요한 조건을 생략하거나 한 번의 요청을 오래가는 성향으로 바꿀 수 있다. 기억의 품질은 저장량보다 **무엇을 남기고, 언제까지 유효하게 보고, 지금 요청에 어떻게 사용하는가**에 달려 있다.

이 장에서 말하는 학습은 사용자를 이해하는 기록과 일을 수행하는 메모를 갱신하는 과정이다. 모델의 가중치를 다시 훈련한다는 뜻이 아니다. 이 둘을 구분해야 “쓸수록 배운다”는 표현이 실제로 무엇을 의미하는지 설명할 수 있다.

## 무엇을 기억으로 다루는가

| 기록 | 쓰임 | 혼동하지 않을 것 |
| --- | --- | --- |
| 대화 원문 | 이전에 실제로 한 말을 다시 찾는다. | AI의 답변과 개발용 요청을 사용자의 발언으로 취급하지 않는다. |
| 현재 맥락(Context) | 이번 요청의 상황·대상·제약을 이해한다. | 일시적 조건을 지속적인 선호로 바꾸지 않는다. |
| 지속 기억(Memory) | 다시 사용할 사실·선호를 출처와 함께 유지한다. | 직접 말한 내용, 추론, 유효 기간, 대체된 기록을 구분한다. |
| 작업 메모(working notes) | 이 사용자를 위해 일하는 방법을 정리한다. | 수행 방법과 사용자에 대한 사실을 섞지 않는다. |
| 하루 기록 | 지난 대화의 상황을 다시 찾는 단서로 사용한다. | 요약을 새로운 사실의 독립적인 근거로 삼지 않는다. |

이것은 저장소 수가 아니라 기록의 목적과 수명을 구분한 표다. 현재 규칙은 [기억·사용자 모델 기준](../secretary-agency-contract.en.md)과 [현재 맥락 기준](../current-context-contract.en.md)에 정의되어 있다.

## 선행 연구에서 가져올 것

LongMemEval은 기억을 정보 추출, 여러 대화를 종합하는 추론, 시간 추론, 정보 갱신, 모르는 질문에 답하지 않기로 나누어 평가한다. 기억 시스템도 색인·검색·읽기의 단계로 분석한다. 따라서 Still에서도 “저장했는가”뿐 아니라 “필요한 기록을 찾아 현재 상황에 맞게 사용했는가”를 따로 확인할 이유가 있다. [R5](references.md#r5)

다만 평가 대상과 저장 정책은 같지 않다. LongMemEval에는 AI가 말한 내용을 다시 찾는 문제도 있다. 그것이 Still에서 AI의 말을 사용자에 관한 사실로 저장해야 한다는 뜻은 아니다. 비교할 것은 능력과 실패 유형이며, 어떤 출처를 지속 기억에 받아들일지는 별도의 정책이다.

Generative Agents는 경험의 기록·검색·성찰·계획을 연결한 설계를 보여 준다. 그러나 주요 평가 대상은 가상 마을의 에이전트 행동이 얼마나 그럴듯한가였다. 이 연구를 실제 사용자 기억의 정확도나 Still의 밤사이 정리 기능이 검증되었다는 근거로 사용할 수는 없다. [R6](references.md#r6)

## 정정은 사실의 유효 범위를 바꾼다

Still의 현재 기준 문서는 새 사실을 추가하고, 대체되는 기존 사실을 무효 처리하는 방식을 설명한다. 이는 바뀐 이유와 되돌릴 대상을 남기기 위한 선택이다. 모든 기록을 영구 보관하자는 뜻은 아니다. “잊어줘”에 따른 무효화와 실제 삭제, 로컬 삭제와 원격 사본 삭제도 구분한다.

가령 “이번 달만 비용을 줄이자”는 이번 달의 조건이다. 이를 “항상 가장 싼 것을 선호한다”로 저장하면 기술적으로는 저장에 성공했어도 이해는 잘못된 것이다. 이 사례는 가상의 설명이며, 실제 사용자 기록을 인용한 것이 아니다.

작성 주체에 따른 권한도 다르다. 사용자가 선택한 자신의 AI는 현재 정책에 따라 기억을 직접 저장하고 알림과 되돌리기를 제공한다. 제3자나 위임받은 작성자의 제안은 승인 전 기억 후보(MemoryCandidate)로 다룬다. 한 경로의 편의를 다른 경로의 권한 확대로 해석하지 않는다.

## 대화 중 저장과 밤사이 정리

대화 중 저장은 방금 이해한 내용을 남긴다. 밤사이 기억 정리(dream)는 여러 요청을 돌아보며 누락된 사실을 찾고, 기록을 정리하고, 작업 메모를 검토한다. 같은 저장 기능처럼 보여도 사용자에게 알리는 방식과 근거의 범위가 다르다.

현재 기준 문서는 대화 중 저장의 알림·되돌리기를 유지하면서, 밤사이의 사실 정리는 조용히 처리하도록 구분한다. 사용자의 판단에 영향을 주는 변경은 관련된 대화에서 드러내고, 작업 메모의 개정은 별도로 알린다. 세부 조건은 [기억·사용자 모델 기준](../secretary-agency-contract.en.md)의 현행 규칙을 따른다.

실패에서 얻는 교훈도 범위를 제한한다. 현재 #496 규칙은 이전 실패 기록을 작업 메모의 근거로만 사용하고, 새로운 사실·기억 무효화·하루 기록의 근거와 분리한다. 한 번의 실패를 사용자 전체의 성향으로 확대하는 대신, 무엇이 잘못됐고 어떤 정정이 있었는지에 맞는 좁은 교훈을 남기려는 선택이다.

## Still의 실험이 말해 주는 범위

[공개 실험 기록](../research/memory-and-dream-experiments-2026-10-22-to-11-05.ko.md)은 맥락 절단, 기억 쓰기 구조, 사실 수집과 정리의 분리, 출처 표시를 비교한다. 여기서 필요한 사실을 더 많이 전달하는 것과, 지난 정보를 현재 사실처럼 노출하지 않는 것은 서로 다른 평가 항목이다.

주요 비교는 과거 이력을 오프라인으로 재생하고 모델이 판정한 결과다. 정답 세트의 사용자 검증과 반복 실행의 변동성에 한계가 있으며, 별도의 소규모 실사용 점검도 전체 정확도를 대표하지 않는다. 조용히 저장된 내용을 사용자가 되돌리지 않았다고 해서 옳았다고 판단할 수도 없다. 이 수치를 LongMemEval 점수나 제품 전체의 기억 정확도로 바꾸어 표현하지 않는다.

남은 과제는 저장·검색·정정·사용을 함께 검증하는 것이다. 정보를 많이 전달하면서도 잘못된 확신은 줄일 수 있는지, 사용자가 오류를 적은 부담으로 바로잡을 수 있는지가 판단 기준이다.
