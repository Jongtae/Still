# 로컬 웹 화면의 역할과 구현 기준

영문 정본: [Local web presentation contract](web-management-contract.en.md). 이 문서는 한국어 요약이며 별도의 정책이나 실행 지시가 아니다.

## 페이지는 대화를 보조한다

현재 방향은 대화 중심 관리다. 사용자는 일을 부탁하거나 설정을 바꾸기 위해 내부 화면 구성을 먼저 익힐 필요가 없어야 한다. 페이지는 텍스트로 담기 어려운 결과, 또는 대화로 안전하게 받을 수 없는 입력을 맡는다. 예전의 ‘웹은 관리 전용 유틸리티’라는 제품 설명은 [Presence 기준 문서](presence-experience-contract.en.md)의 후속 결정 #880으로 대체되었다.

이 문서의 대상은 남아 있는 로컬 결과·설정·승인 화면이다. 지원하는 대화 채널 전체를 정하거나, 별도로 지원되는 브라우저 대화를 금지하는 문서가 아니다. 화면을 바꾸더라도 작업·기억·결과·권한·이력은 Still에 남고, 기존 API와 채널 송수신을 잃지 않아야 한다.

## 탐색과 결과 표시

기존 관리 화면은 작업 현황과 설정을 중심으로 구성된다. AI, 외부 연결, 파일·권한, 기억·개인정보를 관련 기능별로 보여 주고 진단과 예약된 일은 맥락에 맞게 연결한다. 이를 이유로 대화와 별개인 관리 화면을 계속 늘리지는 않는다.

이전의 모든 기록을 모아 보는 메뉴는 #562에서 제거되었다. 저장 항목은 해당 작업에 실제로 연결된 기록이나 유형별 설정에서 `#item/<유형>/<id>`로 연다. 응답 문구나 키워드로 결과 파일의 존재를 추측하지 않는다. 메뉴가 없어져도 데이터가 삭제되거나 다른 권한 범위로 옮겨지는 것은 아니다.

메뉴는 하나로 유지하고 선택하면 본문을 전환한다. 대화 아래에 화면을 계속 붙이거나 같은 메뉴를 두 번 두지 않는다. 뒤로 가기, 선택, 스크롤, 포커스와 입력 중인 내용을 보존한다. 프로젝트는 선택적인 묶음이지 필수 설정이나 파일 경로가 아니다.

작업 상세는 요청과 실제 상태, 결과 또는 사용자가 해야 할 일, 관찰된 실행 과정과 출처, 선택해서 펼치는 기술 상세 순서로 읽힌다. 결과 파일에는 실제 열기 동작이 있어야 한다. 실패·부분 완료·중단·미확인을 구분하고, 진행률·예상 완료 시각·모델 정보를 만들어내지 않는다. 취소 요청과 실제 취소, 이미 일어난 외부 효과도 구분한다.

## 기록과 파일은 유형에 맞게 다룬다

메모, 지속 기억, 기억 후보, 임시 자료, 결과물은 내부 유형과 수명이 다르다. 표시와 삭제·승인 동작이 실제 유형과 맞아야 한다. 제3자의 기억 후보는 승인 전에는 저장된 기억이 아니다. 사용자 자신의 AI가 저장하는 경로는 [기억 기준 문서](engineering/contracts/memory.en.md)를 따른다.

기록을 지운다고 원본 파일을 함께 지우거나, 결과물 삭제를 기억 삭제 API에 보내서는 안 된다. 거부된 작업도 성공으로 표시하지 않는다. 참고 폴더는 입력을 읽는 곳, 결과 저장 폴더는 생성 파일을 쓰는 곳이다. 이름을 단순하게 만들더라도 서로 다른 기존 폴더 권한을 조용히 합치지 않는다.

## 연결과 입력 상태를 정확하게 보여 준다

설정 저장, 사용자 로그인 확인, 준비 상태 검사, 실제 실행 확인은 서로 다르다. 직접 API를 편집하거나 검사했다고 선택된 구독 AI가 바뀌는 것은 아니다. 사용하지 않는 제공자의 API 키가 없다는 이유로 AI 전체를 미연결로 표시하지 않는다. 로컬 실행을 로컬 전용 모델 처리로 설명하지도 않는다.

설정 변경은 **수정안 입력 → 바로 그 수정안 검사 → 성공 후 적용** 순서를 지킨다. 실패하거나 입력이 바뀌면 기존 연결을 유지하고 다시 검사한다. 다른 목적지에 예전 키를 넘기거나, 설정 화면을 열기만 했는데 유료 요청을 보내서는 안 된다. 실제 제공자에 접속하는 검사를 무료·오프라인으로 표현하지 않는다.

이미 연결된 서비스에는 빈 인증 양식 대신 현재 상태와 변경 동작을 보여 준다. 설명과 오류는 관련 입력 옆에 두며 장문의 반복 안내는 피한다. 주기적 갱신과 화면 전환으로 입력, 커서, 검색 결과, 확인 중인 내용이 사라지지 않아야 한다.

## 과거 구현 지시와 현재 검증을 분리한다

#379/#380과 #382 WEB-ADMIN-01은 이전 저장소의 결정·구현 기록이다. 당시 W0 준비와 별도 승인 뒤의 W1–W3를 새 작업 순서로 재사용하지 않는다. [옛 시안 안내](design/utility-v1/README.md)와 [인계 포인터](design/utility-v1/CODEX_PROMPT.txt)는 출처와 자동 실행 금지 원칙을 남긴다.

현재 작업은 선택한 이슈와 루트 계획을 따른다. 문서 작성·준비 기록·문서 병합만으로 작업자, 예약 실행, 모델 호출이나 배포가 시작되지 않는다. 화면을 수정할 때는 영향을 받는 상호작용과 데이터 보존을 검사하고, 모의 브라우저 검사와 실제 사용자 관찰을 구분한다. 화면 설명을 고쳤다는 사실만으로 현재 설치의 사용성이 검증되었다고 보고하지 않는다.
